# Echo Trading 제품 카탈로그

첨부된 제품마스터의 **385개 제품 / 14개 카테고리**를 반영한 고객 열람용 정적 웹사이트입니다. HTML, CSS, 순수 JavaScript로 만들었으며 별도의 서버, 유료 서비스, npm 설치 없이 실행할 수 있습니다. 외부 폰트·CDN·추적 스크립트를 사용하지 않습니다.

## 1. 먼저 열어보기

ZIP 압축을 풀고 `index.html`을 Chrome 또는 Edge로 여세요. 폴더 구조를 유지해야 합니다. 제품 데이터는 `data/products.js`에서 읽으므로 파일을 직접 열어도 동작합니다.

- PC: 제품 비교표, 카테고리, 검색 및 세부 분류·어플리케이션 필터
- 모바일: 가로 스크롤 없이 읽는 제품 카드, 가로 스크롤 카테고리
- 제품명을 클릭하면 지표성분·규격/함량 등 상세정보 표시
- 20개 단위 페이지 이동 / 제품명순·제품코드순 정렬
- 전화 문의 및 회사 홈페이지 연결

## 2. GitHub Pages로 공개하기

1. GitHub에 새 저장소를 만드세요. 예: `echo-catalog`.
2. **Add file → Upload files**에서 압축을 푼 폴더의 **내용물**을 올리세요. 저장소 첫 화면에 `index.html`, `assets`, `data`가 바로 있어야 합니다. ZIP 자체를 업로드하거나 상위 폴더로 한 번 더 감싸지 마세요.
3. **Commit changes**를 눌러 저장하세요.
4. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**로 설정하세요.
5. Branch는 **main**, 폴더는 **/(root)**를 선택하고 **Save**하세요.
6. 배포가 끝나면 Pages 설정에 표시되는 주소를 열어 고객에게 공유하세요. 일반적인 주소 형태는 `https://사용자명.github.io/echo-catalog/`입니다.

이 패키지는 GitHub 업로드용으로 준비되었으며, 현재 GitHub 계정에 업로드하거나 공개 배포한 상태는 아닙니다. GitHub Free에서는 공개 저장소를 사용하는 방식으로 진행할 수 있습니다. 요금제·조직 정책에 따라 지원 범위가 다릅니다.

공식 안내: [GitHub Pages 게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 3. 코드를 몰라도 제품 수정·추가하기

1. 현재 버전 폴더의 `manage.html`을 여세요.
2. 왼쪽에서 제품을 검색·선택하거나 **새 제품 추가**를 누르세요.
3. 정보를 수정한 뒤 **목록에 반영**을 누르세요. 제품코드는 중복될 수 없습니다.
4. 필요한 제품을 모두 수정한 뒤 **products.js 다운로드**를 누르세요.
5. 내려받은 파일 이름이 `products (1).js` 등으로 바뀌었다면 `products.js`로 바꾸세요.
6. 로컬 폴더의 `data/products.js`와 교체하고 `index.html`을 새로고침해 확인하세요.
7. GitHub에서는 **data 폴더를 먼저 열고 → Add file → Upload files**로 해당 파일을 올린 후 Commit changes 하세요.
8. Pages 배포가 끝나면 고객 화면을 새로고침하세요. 이전 내용이 보이면 Windows에서 Ctrl+F5를 누르세요.

**제품 편집기는 로컬 파일을 내려받는 도구입니다.** 서버 저장이나 관리자 로그인 기능이 없습니다. 다른 방문자가 편집기를 열더라도 웹사이트 원본을 변경할 수 없습니다. `manage.html`과 `assets/manage.js`는 공개 사이트 실행에 필요 없으므로 원하면 업로드에서 제외하고 PC에서만 보관하세요.

브라우저를 닫으면 다운로드하지 않은 편집 내용은 사라집니다. **JSON 백업**을 내려받으면 나중에 **JSON 불러오기**로 이어서 작업할 수 있습니다. 불러오기는 현재 목록 전체를 교체합니다.

‘고객 목록에 표시’ 해제는 화면에서 숨기는 기능입니다. 데이터 파일 안에는 남으므로 비밀정보를 보관하는 기능으로 사용하지 마세요. 완전히 제외하려면 제품을 삭제하고 새 데이터 파일을 배포하세요.

## 4. 엑셀을 다시 받아 일괄 반영하기

원본 엑셀은 내부 PC에 보관하세요. 공개 저장소에 업로드할 필요가 없습니다.

이 방법만 Python과 openpyxl이 필요합니다. 최초 한 번 터미널에서 `python -m pip install openpyxl`로 설치한 뒤, 프로젝트 폴더에서 `python scripts/import_excel.py "원본엑셀의 전체경로.xlsx"`를 실행하세요. Windows에서 python 대신 py를 사용해도 됩니다.

변환 결과는 `data/products.js`에 기록됩니다. 점검 목록까지 받으려면 `--review "공개폴더 밖의 경로/review.json"` 옵션을 추가하세요. 원본의 **제품마스터** 시트와 아래 열 이름을 기준으로 읽습니다. 열 순서는 바꾸어도 됩니다.

**일괄 변환은 전체 목록을 덮어씁니다.** 편집기 수정 내용과 자동 병합되지 않으므로 변환 전에 백업하고, 장기적으로는 원본 엑셀을 기준 데이터로 관리하세요.

| 엑셀 열 | 데이터 키 | 고객 표시 |
|---|---|---|
| 제품코드 | id | 제품 식별 및 문의용 코드 |
| 아이템 | name | 제품명 |
| 대분류 | category | 원료 카테고리 |
| 상세 분류 | subcategory | 세부 분류 |
| 지표성분 | marker | 지표성분 |
| 수치 | spec | 상세창의 규격 / 함량 |
| 포장 | packaging | 포장단위 |
| 원산지 | origin | 원산지 |
| 기능 | function | 주요 특성 |
| 사용처(Application) | application | 어플리케이션 |
| 형태 | form | 상세창의 형태 |

## 5. 데이터 반영 기준

- 원본 385행을 고유 제품코드 기준으로 모두 유지했습니다. 같은 제품명도 별도 코드·규격일 수 있어 임의로 합치지 않았습니다.
- 기존 14개 분류 체계를 유지했습니다. 새로운 카테고리를 입력하면 메뉴도 자동으로 늘어납니다.
- `English / 한국어` 형식은 분류·주요 특성·어플리케이션에서 한국어 중심으로 표시합니다. 지표성분은 원문을 유지합니다.
- 지표성분과 ‘수치’는 의미가 항상 일치하지 않으므로 임의로 연결하지 않고 별도로 표시했습니다.
- 원본의 ‘기능’은 영양·향미 등 용도 태그를 포함합니다. 이를 건강기능식품의 인정된 기능성 문구로 바꾸지 않고 **주요 특성**으로 표기했습니다. 필요한 경우 담당자가 제품별 확정 자료에 맞게 편집할 수 있습니다.
- 원본에 없는 효능, 규격, 원산지, 포장단위는 생성하지 않았습니다. 빈 항목은 **문의**로 표시합니다.
- ‘확인필요’ 등이 붙은 미확정 지표성분, 단위 없는 수치, 미확정 적용 분야, 의미 불명 원산지, 포장란의 업체명·가격·MOQ·운송 메모 등은 공개값에서 비웠습니다. 점검 목록은 공개 ZIP 밖에 별도 제공됩니다.
- **제조사·매입처 열은 공개 데이터에서 제외**했습니다. 원본 Excel과 점검 목록도 공개 ZIP에 넣지 않았습니다. 사이트 데이터를 복사해 게시하기 전에 회사에서 공개할 제품·정보 범위를 확인하세요.
- 엑셀 자체를 실시간 DB로 연결한 구조는 아닙니다. 데이터 파일을 교체할 때 갱신되는 방식입니다.

## 6. 파일별 역할

| 파일 | 역할 |
|---|---|
| index.html | 고객 화면 구조·회사정보 |
| assets/styles.css | 색상·폰트·레이아웃·모바일 디자인 |
| assets/app.js | 검색·필터·페이지 이동·상세보기 |
| assets/favicon.svg | 브라우저 아이콘 |
| data/products.js | 고객용 제품 데이터 전체 |
| manage.html | 로컬 제품 편집기 |
| assets/manage.js | 편집·추가·삭제·다운로드 처리 |
| scripts/import_excel.py | 내부 엑셀 → 고객용 데이터 변환 |
| .nojekyll | GitHub Pages의 정적 파일 처리 |
| .gitignore | 로컬 git 사용 시 내부 엑셀 등 제외 |

회사정보는 `index.html`의 header/footer, 대표 색상은 `assets/styles.css` 첫 줄의 `:root` 변수를 수정하세요. 로고는 제공된 공식 파일이 없어 텍스트 워드마크로 구성했습니다.

## 7. 자주 발생하는 문제

- **목록이 안 뜸:** index.html만 이동하지 않았는지, data/products.js가 같은 상대 경로에 있는지 확인하세요.
- **제품 수정이 안 보임:** 편집기의 ‘목록에 반영’만으로는 게시되지 않습니다. 다운로드 → 파일 교체 → GitHub commit → 배포 완료 단계가 필요합니다.
- **GitHub 404:** index.html의 위치와 Pages의 main / root 설정을 확인하세요.
- **데이터 가져오기 실패:** 시트 이름과 열 제목을 유지하고 제품코드를 빠짐없이 고유하게 입력하세요.

모든 외부 홈페이지 연결은 사용자가 제공한 회사 주소를 적용했습니다. 외부 사이트의 운영 상태는 별도로 검증하지 않았습니다.

## 검증 범위

제품 건수·고유 코드·분류 수·공개 필드 제한과 JavaScript 구문, 파일 경로를 확인했습니다. 실행 환경의 브라우저 접근 제한으로 실제 브라우저 화면 검증은 완료하지 못했습니다.

## 상위 분류 탭 (추가)

맨 위에서 건강기능식품 / 일반식품 / 식품첨가물을 선택합니다. 일반식품 안에는 일반원료와 기능성부원료가 있습니다. 기존 14개 원료 분류는 선택한 상위 분류의 하위 필터로 유지됩니다.

- 포도추출분말(멜라토닌 1%), BE0072: 사용자 지정에 따라 일반식품 → 기능성부원료에 배치했습니다.
- 원본에 명시된 구분 9건과 사용자 지정 1건을 반영했습니다. 나머지 375건은 상위 분류를 추정하지 않고 전체 제품에 유지했습니다.
- 건강기능식품 1건 / 일반식품 5건 / 식품첨가물 4건으로 시작합니다. 이 배치는 카탈로그 탐색용이며 원본의 ‘미검증’·‘공급품 동일성 미확인’ 조건까지 검증한 법적 분류 판정이 아닙니다. ‘기능성부원료’는 판매용 하위 카테고리 이름이며 새로운 효능 문구를 추가하지 않았습니다.
- 편집기에서 상위 분류 및 일반식품 하위 분류를 선택할 수 있습니다. 건강기능식품·식품첨가물에는 일반식품 하위 분류를 저장하지 않습니다.
- 엑셀에 선택 열 ‘상위분류’, ‘일반식품 하위분류’를 추가하면 일괄 변환 때도 유지합니다. 값은 편집기와 동일한 명칭을 사용하세요.
- 데이터 키는 catalogType / catalogGroup입니다. 이름이나 성분만으로 나머지 제품을 자동 분류하지 않습니다.

## 선택 제품 소개자료 인쇄 / PDF 저장

1. 고객 화면에서 원하는 제품의 **자료에 담기** 체크박스를 선택하세요. **현재 페이지 선택**은 보이는 최대 20개만 선택합니다.
2. 검색, 원료 분류, 상위 탭, 페이지를 바꿔 다른 제품도 선택할 수 있습니다. 선택은 브라우저를 새로고침하거나 닫기 전까지 유지됩니다. 같은 제품코드는 한 번만 포함됩니다.
3. **선택 제품 소개자료 / PDF**를 누르세요.
4. 자료 제목, 고객사명, 전달 메모를 입력하고 출력할 열을 고르세요. 제품명은 항상 포함됩니다. 지표성분과 규격/함량은 별개 열입니다.
5. **출력 제품**을 펼치면 선택 목록을 확인하거나 제품을 제외할 수 있습니다. 출력 순서는 선택 순서이며, 현재 페이지에 없는 선택 제품도 모두 포함됩니다.
6. **인쇄 / PDF 저장**을 누르고 프린터 또는 **PDF로 저장**을 선택하세요. 브라우저 인쇄창을 사용하는 방식이며, PDF 파일을 즉시 자동 다운로드하는 기능은 아닙니다.
7. **A4 / 가로 / 배율 100%** 기준으로 확인하세요. **배경 그래픽**을 켜고 **머리글 및 바닥글**을 끄면 파란 제목줄과 연녹색 표가 깔끔하게 나옵니다. 출력 전에 시스템 인쇄 미리보기의 페이지 수와 줄바꿈을 확인하세요.

출력은 선택 제품으로 만든 별도 문서이며 검색창·탭·버튼은 제외합니다. 표 제목과 연락처는 여러 페이지에서 반복되도록 구성했습니다. 제품 수나 긴 텍스트에 따라 자동으로 페이지가 나뉩니다. 화면 미리보기는 내용 확인용이며 실제 인쇄 페이지 경계는 브라우저에서 정합니다.

새 파일 `assets/print.js`, `assets/print.css`를 기존 파일과 함께 업로드하세요. 단일 파일 `Echo-Trading-Catalog.html`에서도 동일한 기능이 동작합니다. 고객사명과 메모는 브라우저 안에서만 처리하며 서버로 보내지 않습니다.

검증: DOM 시뮬레이션으로 페이지·탭 간 선택 유지, 현재 페이지 선택, 선택 제품만 출력, 출력 열 변경, 제품 제외, 빈 선택 버튼 비활성화, 인쇄 전후 복귀를 확인했습니다. 실행 환경에 브라우저가 없어 실제 인쇄/PDF의 시각 검증은 완료하지 못했습니다.
