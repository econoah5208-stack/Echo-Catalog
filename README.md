# Echo Trading 웹사이트 · 식품원료 제품 카탈로그 (v9.3)

HTML·CSS·순수 JavaScript로 만든 정적 웹사이트입니다. 서버·데이터베이스·빌드 과정 없이 `index.html`을 열거나 GitHub Pages에 올리면 바로 동작합니다.

v9.0은 회사소개서(2026)의 브랜드 체계를 웹에 적용한 디자인·정보 구조 개선판입니다. v9.1은 여기에 세 번째 출력 방식 **A4 세로 · 인체 기능형 카탈로그**를 더했고, v9.2는 그 출력의 일반 식품원료 분류를 원료 종류별(곡류·과실류·채소·농축액·향미·조미·감미료·당류 등)로 나누고 여백이 남으면 여러 분류를 한 페이지에 이어 배치해 종이를 줄였습니다. 385개 제품 카탈로그, 검색·분류, 제품 상세, 선택 제품 누적, 기존 A4 가로(최대 25개)·A4 세로 압축(최대 50개) 출력, 제품 편집기 기능은 그대로 유지합니다.

### 두 가지 탐색 축

- **국내 식품분류**(상단 탭, 검정색 선택 표시): 전체 / 건강기능식품 / 일반식품(일반원료·기능성부원료) / 식품첨가물
- **원료 분야**(왼쪽 메뉴, 오렌지 선택 표시): 8개 원료 분야 → 해당 분야의 대분류

두 축은 함께 적용됩니다. 예: `건강기능식품` + `식물추출물·기능성 소재` = 14개.

### 검색·필터 동작

- 검색: 제품명, 제품코드(대소문자 무관), 지표성분 등 모든 공개 항목. 띄어쓰기로 여러 단어를 입력하면 모두 포함된 제품만 표시
- 적용된 조건은 칩으로 표시되며 칩마다 개별 해제
- `필터 초기화`: 원료 분야·대분류·소분류·어플리케이션만 해제(검색어와 국내 식품분류 유지)
- `전체 제품 보기`: 검색어와 모든 조건 해제(385개)
- 결과가 없으면 검색어 지우기 / 필터 초기화 / 다른 식품분류 / 전체 보기 버튼을 결과 수와 함께 제시
- 현재 조건과 페이지는 주소(`?q=…&area=…&page=…`)에 저장되어 새로고침·뒤로 가기 후에도 유지됩니다. 로컬 파일로 열 때는 탭 안에서만 유지됩니다.

## 제품 소개자료 / PDF

목록에서 제품을 체크하거나 상세 화면의 `소개자료에 담기`, 또는 `인쇄 / PDF 저장` 창의 빠른 출력 범위로 제품을 고릅니다. 선택은 페이지를 넘겨도 누적됩니다.

- 빠른 출력 범위: 전체 / 일반식품 / 건강기능식품 / 식품첨가물 / 비타민·미네랄 / 농축액·추출액·퓨레 / 분말 / 효모,유산균 유래 / Stock 운용 제품
- Stock 운용 여부 필터: 전체 / 운용 / 미운용 / 미정
- 자료 제목, 고객사명, 전달 메모(첫 페이지), 출력 항목 선택
- `인쇄 레이아웃 / 분량`에서 세 가지 중 하나를 고릅니다(라디오 버튼).

| 레이아웃 | 페이지당 | 특징 |
|---|---|---|
| A4 가로 · 상세 제품 목록 (기본) | 최대 25개 | 최소 장수 자동 계산, No.·국내 식품분류·대분류·제품명/코드 고정, 분류 셀 병합 |
| A4 세로 · 압축 제품 목록 | 최대 50개 | 최소 장수 자동 계산, 공통 글자 크기 자동 조정, 페이지 넘침 방지 |
| A4 세로 · 인체 기능형 카탈로그 (v9.1~) | 최대 22개 | 21개 분류별 배치(여백이 남으면 다음 분류를 같은 페이지에), 인체 그래픽·분류 인덱스, 글자 크기 고정·실측 분할 |

- 가로형·압축형 순번은 이번 출력 목록 기준 1부터 연속, 정렬은 건강기능식품 → 일반식품 → 식품첨가물, 대분류 가나다순, 제품명 가나다순
- 미리보기 배율(축소·확대·화면 너비에 맞춤)은 화면 표시용이며 A4 실제 크기는 바뀌지 않습니다.
- 출력 항목은 레이아웃마다 따로 기억합니다. 레이아웃을 바꿀 때 자료 제목이 기본값이면 `제품 소개자료` ↔ `기능별 원료 포트폴리오`로 함께 바뀌고, 직접 입력한 제목은 그대로 둡니다.

권장 인쇄 설정: 대상 `PDF로 저장`, 용지 A4, 배율 100%, 배경 그래픽 켜기, 브라우저 머리글·바닥글 끄기. 인체 기능형은 인체 그래픽과 머리띠 색이 배경 그래픽이므로 `배경 그래픽`을 반드시 켜 주세요.

v9.0에서 고친 인쇄 문제: 가로형에서 `효능` 항목을 선택하면 인쇄 전용 셀 여백 때문에 페이지 하단 1~2행이 잘리던 현상(v8.4에도 있음)을 수정했고, 가로형 자동 맞춤에 약 1.6mm 안전 여유를 두었습니다.

## A4 세로 · 인체 기능형 카탈로그 (v9.1, v9.2 개선)

선택한 제품을 `data/body-functions.js`의 대표 분류(인체 기능 01~10, 원료 종류 11~20, 확인 필요 21)별로 묶어 A4 세로 카탈로그를 만듭니다. v9.2부터는 한 분류가 끝나고 페이지에 여백이 남으면 다음 분류를 같은 페이지에 이어서 배치합니다. 분류마다 머리띠와 표 머리글이 따로 붙어 구분됩니다.

### 페이지 구성

| 영역 | 내용 |
|---|---|
| 머리글 | 로고, `FUNCTIONAL INGREDIENT PORTFOLIO`, 자료 제목(기본 `기능별 원료 포트폴리오`), 고객사명(입력 시 `○○ 귀중`), 이 페이지에 실린 분류명 전부(예: `02 호흡기 · 03 심혈관 · 혈액`), 페이지 `n / 전체` |
| 전달 메모 | 첫 페이지에만 표시 |
| 왼쪽 패널(폭 약 38mm · 약 20%) | `BODY MAP` 인체 실루엣(32×64mm, 고정 크기) — 이 페이지의 인체 기능 부위는 오렌지 원(여러 개 가능), 다른 부위는 연회색 원. 07 면역은 실루엣 전체를 옅은 오렌지로 표시. 아래에 기능 인덱스(01~10)·식품 원료 분류(11~21)와 각 분류의 시작 페이지, 맨 아래 범례 |
| 오른쪽 표(약 80%) | 분류마다 머리띠(번호·영문명·분류명·원료 수·`1 / 2` 같은 이어짐 표시) + 표. 기본 열은 `NO.` · `제품명`(제품코드·국내 식품분류 보조줄) · `기능 / 특징`(효능 문장 + 주요 특성 칩 + `관련` 보조 기능 태그) |
| 바닥글 | `ECHO TRADING`, 회사명·연락처(`data/site-config.js` 값 그대로), 참고 분류 안내문, 출력일, 페이지 번호 |

- 인체와 표의 연결: 인체 기능 분류 조각마다 얇은 오렌지 선 1개(부위 원 → 왼쪽 패널 경계 → 두 패널 사이 여백(세로) → 해당 머리띠)를 그립니다. 제품 행마다 선을 긋지 않습니다. 한 페이지에 인체 기능 분류가 여럿이면 여백 안에 세로선 자리를 나눠 주고, 선끼리 교차하지 않는 배치를 자동으로 고릅니다. 선 좌표는 렌더링된 위치를 mm로 측정해 그립니다.
- 부위 원은 01→10 순서대로 위에서 아래로 놓여 있습니다(머리·목·가슴·간·배·아랫배·허리(면역 시작점)·허벅지·무릎·종아리). 이 순서 덕분에 한 페이지에 여러 분류가 함께 나와도 선이 교차하지 않습니다. v9.2에서 10 피부·모발 원을 팔에서 종아리로 옮겼습니다.
- 11~21번(원료 종류·확인 필요) 분류는 부위를 강조하지 않고 연결선도 없습니다. 이 분류만 있는 페이지는 인체 그래픽 아래에 `이 분류는 특정 인체 부위와 연결하지 않습니다.`를 표시합니다. 머리띠 색은 인체 기능 오렌지, 원료 종류 차콜, 확인 필요 회색입니다.
- 출력 항목: 제품명 아래 보조줄(제품코드·국내 식품분류), `기능 / 특징` 열 안(효능·기능 설명, 주요 특성, 관련 기능 태그)은 자유롭게 켜고 끕니다. 별도 열(지표성분 30mm, 원산지 16mm, 포장단위 16mm)은 **최대 2개**까지만 선택되며, 3번째를 고르면 선택이 거절되고 안내 문구가 표시됩니다.
- `페이지 구성 › 분류마다 새 페이지에서 시작`을 켜면 v9.1처럼 분류마다 새 페이지를 씁니다(기본은 꺼짐 = 종이 절약).
- 효능 문장이 비어 있으면 주요 특성 문장을, 그것도 없으면 `효능 정보 문의`를 표시합니다. DB 문장은 고치거나 새로 만들지 않습니다.

### 페이지 나누기 규칙

1. 분류 번호 순서(01 → 21)대로, 분류 안에서는 제품명 가나다순으로 정렬합니다.
2. 별도 측정 영역(`#print-measure-body`, 화면 밖)에 실제 A4 페이지를 만들고 한 행씩 넣어 보며 마지막 표가 목록 영역 아래 6px 안전 여유를 넘기 직전까지 채웁니다(페이지당 상한 22개, 여러 분류 합계 기준).
3. 한 분류가 끝난 페이지에 여백이 남으면 다음 분류를 이어서 시작합니다. 다만 제품 6개 미만인 분류는 나누지 않고(다 들어가지 않으면 다음 페이지로), 나눌 때는 이 페이지 조각과 다음 페이지 조각이 각각 3행 이상이 되게 합니다.
4. 글자 크기는 줄이지 않습니다(본문 7.8pt, 제품명 8.6pt, 보조줄·태그 6.4~6.6pt 고정). 설명이 길면 페이지당 제품 수가 줄고 장수가 늘어납니다.
5. 순번은 출력 전체 기준 1부터 연속, 동일 제품은 대표 분류에서 한 번만 출력됩니다. 분류 파일에 없는 제품도 21번으로 반드시 출력됩니다.
6. 행은 페이지 경계에서 잘리지 않고(`break-inside: avoid`), 표 머리글은 분류 조각마다 다시 표시됩니다.

참고 결과(2026-10-23, Chromium 측정): 전체 385개 → 22장(14장은 2개 이상 분류), 분류마다 새 페이지로 하면 28장, 지표성분·원산지 열 추가 시 27장. 부분 선택은 5개 1장, 20개 3장, 50개 5장, 100개 7장입니다(v9.1은 4·9·11·14장).

### 인체 기능 분류 관리 (`data/body-functions.js`)

원본 제품 데이터(`data/catalog.js`)는 바꾸지 않고 이 파일에서만 분류를 관리합니다. 현재 값은 **회사 검토 전 1차 초안**입니다.

```js
areas:    [{ id:'gut', no:'05', kind:'body', name:'장 · 소화', title:'장 건강 · 소화 관련 원료', en:'DIGESTIVE HEALTH', hint:'…', anchor:'gut' }, …]  // 분류 21개
anchors:  { gut: { x:50, y:72 }, … }            // 인체 그래픽 강조 위치(가로 100 × 세로 200 좌표, 01→10 순으로 위→아래)
products: { 'BE0002': ['gut'], 'BE0022': ['gut', 'meta'], … }  // [대표 분류, 보조 태그…]
notes:    { 'AF0019': '…' }                     // 분류 판단 근거·확인 메모(출력 안 됨)
```

| 구분 | 번호 · 분류 | kind | 현재 제품 수 |
|---|---|---|---|
| A. 인체 기능 관련 | 01 뇌·신경 / 02 호흡기 / 03 심혈관·혈액 / 04 간 / 05 장·소화 / 06 대사·활력 / 07 면역 / 08 근육·운동 / 09 뼈·관절 / 10 피부·모발 | `body` | 19 / 3 / 18 / 7 / 34 / 49 / 12 / 9 / 17 / 15 (183) |
| B. 원료 종류 | 11 일반 영양 원료 / 12 곡류·두류 / 13 과실류 유래 / 14 채소·서류 / 15 농축액·퓨레·페이스트 / 16 향미 / 17 조미·산미 / 18 감미료 / 19 당류 / 20 식품 가공·물성 | `general` | 38 / 12 / 27 / 8 / 56 / 9 / 13 / 2 / 13 / 17 (195) |
| 확인 필요 | 21 기타 · 분류 확인 필요 | `review` | 7 |

v9.2에서 v9.1의 `12 향미·감미·조미`(137개)를 원료 종류별로 나눴고, 미배아추출분말(BE0032)·10곡통곡물발효효소분말2x(MX0001)는 곡류로, 피세틴 라임추출물분말(BE0073)은 과실류 유래로 옮겼습니다. 인체 기능 근거가 있는 과일·곡물 추출물(예: 타트체리추출분말)과 올리고당·락추로스는 01~10에 그대로 둡니다.

분류 기준(파일 머리 주석에도 있음):

1. 대표 분류는 DB `효능`에 적힌 첫 번째 구체적 인체 기능입니다. `항산화`, `영양 공급`, `에너지 공급`, `풍미`처럼 부위를 가리키지 않는 표현은 인체 부위에 연결하지 않습니다.
2. 인체 기능 근거가 없는 원료는 원료 종류·제조 역할로 11~20번에 둡니다. 효능 문구에 건강 표현이 있어도 언급된 기능은 보조 태그로만 표시합니다. 겹칠 때의 우선순위는 다음과 같습니다.
    1. 조미·산미·향미·감미료·당류 — DB 대분류가 조미 원료·식초·산미료·향료·당류·감미료인 원료. 18 감미료는 고감미도 감미료(수크랄로스·스테비아), 19 당류는 당알코올·벌꿀·시럽·이당류
    2. 곡류·두류 — 형태와 관계없이(곡물 농축액·페이스트·발효분말 포함)
    3. 농축액·퓨레·페이스트 — 과일·채소·견과·식물 농축액, 퓨레, 페이스트
    4. 나머지 과일 원료(분말·농축분말·착즙액·건조 과일·과일 추출물)는 13 과실류 유래, 채소·서류 분말은 14 채소·서류
3. 효능 정보가 없거나, 규격서 확인이 필요하거나, 질병 관련 표현이 있는 제품은 21번입니다.
4. 같은 원료(성분)의 제품은 같은 분류를 씁니다.
5. 키워드 자동 분류가 아니라 제품별 효능·주요 특성·대분류·소분류를 읽고 정한 값입니다. 새 효능이나 질병 예방·치료·개선 표현을 만들지 않았습니다.

수정 방법:

1. `products`에서 제품코드의 배열을 고칩니다. 첫 값이 대표 분류(출력 위치), 나머지는 `관련` 태그입니다. id는 `areas`의 id만 쓸 수 있습니다.
2. 판단 근거가 필요하면 `notes`에 적습니다.
3. 새 제품을 추가했는데 분류를 아직 정하지 않았다면 그대로 두어도 됩니다. 21번 `기타 · 분류 확인 필요`로 자동 출력됩니다.
4. `node scripts/verify_catalog.mjs`로 점검합니다. 없는 분류 id·잘못된 태그·위치가 없는 부위는 오류로, 카탈로그에 없는 제품코드와 분류되지 않은 제품은 경고로 알려 주고, 분류 합계가 전체 제품 수와 같은지 확인한 뒤 분류별 제품 수를 출력합니다.
5. `manage.html`에서 제품을 고르면 그 제품이 인체 기능형 출력에서 어느 분류로 나오는지 표시됩니다(분류 변경은 이 파일에서만 합니다).

분류명·부위 위치를 바꾸려면 `areas`·`anchors`를 수정합니다. 분류를 새로 만들면 `areas`에 추가한 순서가 출력 순서입니다. 부위 위치를 옮길 때는 01→10 순서대로 세로 좌표가 커지도록 두세요(점검 스크립트가 순서가 어긋나면 경고합니다). 옮긴 뒤에는 연결선이 다른 원을 지나가지 않는지 미리보기에서 확인하세요.

## 제품 수정·추가 (manage.html)

1. `manage.html`을 엽니다(현재 `data/catalog.js`를 자동으로 불러옴).
2. 제품을 선택하거나 `새 제품 추가`를 누릅니다. 대분류는 기존 목록에서 고를 수 있고, 연결될 원료 분야가 함께 표시됩니다.
3. `목록에 반영` → `웹용 데이터 다운로드`.
4. 내려받은 `catalog.js`로 `data/catalog.js`를 교체합니다.

관리 페이지는 브라우저 안에서만 동작합니다. 로그인·권한 확인·서버 저장 기능이 없습니다. 사이트와 함께 공개 저장소에 올리면 주소를 아는 사람은 열 수 있으므로, 공개 범위가 걱정되면 `manage.html`과 `assets/manage.js`를 공개 저장소에서 빼고 사내 PC에서만 사용하세요.

## Excel 일괄 반영

Python 3와 `openpyxl`, Node.js가 필요합니다. 원본 Excel과 점검 파일은 저장소 밖에 두세요.

```bash
python scripts/import_excel.py "원본엑셀.xlsx" --output "../private/catalog-import.json" --review "../private/review.json"
node scripts/build_catalog.mjs "../private/catalog-import.json" "data/catalog.js"
node scripts/verify_catalog.mjs --compare "../private/catalog-import.json" --expect 일반식품=300,건강기능식품=42,식품첨가물=43,일반원료=179,기능성부원료=121
```

`verify_catalog.mjs`는 제품 수·코드 중복, 공개 필드 화이트리스트(비공개 필드 차단), 국내 식품분류 수치, 원료 분야 매핑 누락과 합계, 원산지 국가 수, 공개값 안의 내부 메모 의심 문구를 점검합니다. `--expect`의 기대 수치는 Excel이 바뀌면 함께 바꾸세요.

일반식품 하위 분류(일반원료/기능성부원료) 기준은 코드가 아니라 `scripts/general_food_groups.json`에서 관리합니다. 우선순위는 ① Excel에 `일반식품 하위분류` 열이 있으면 그 값 ② 제품코드 접두사(`BE`) ③ 목록에 있는 제품코드 ④ 나머지는 일반원료입니다. 장기적으로는 Excel에 `일반식품 하위분류` 열을 추가해 관리하는 것을 권장합니다.

| Excel 열 | 데이터 키 | 표시 용도 |
|---|---|---|
| 제품코드 | id | 제품 식별 코드 |
| 아이템 | name | 제품명 |
| 국내 식품분류 | catalogType | 건강기능식품 / 일반식품 / 식품첨가물 |
| (일반식품 하위분류, 선택) | catalogGroup | 일반원료 / 기능성부원료 |
| 대분류 | category | 대분류(원료 분야 연결 기준) |
| 소분류 | subcategory | 소분류 |
| 지표성분 | marker | 지표성분 |
| 수치 | spec | 규격 / 함량 |
| 기능 | function | 주요 특성 |
| 효능 | efficacy | 확정된 효능(확인·검토·미정 값 제외) |
| 사용처(Application) | application | 어플리케이션 |
| 형태 | form | 형태 · 분말 출력 범위 |

`제조사·매입처` 열은 변환하지 않습니다. 포장란의 업체명·가격·MOQ·운송 메모와 미확정 값은 고객 표시값에서 제거하고 점검 파일에 기록합니다.
